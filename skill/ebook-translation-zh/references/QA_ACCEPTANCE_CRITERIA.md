# QA 验收标准

PASS 必须同时满足：跨页逻辑段落未拆分；图片仅在完整段落后且不重不漏；注释连续、一一绑定、原位显示且文末无重复；HTML 无视觉斜体、外部依赖、绝对临时路径或资源缺失；首次专名满足双语规则；HTML/Markdown block_id 顺序一致；Markdown/Vault 可见正文一致；图片哈希一致；UTF-8 与 YAML 有效。

多章节 QA 还必须核对：译文中的页码标记与 source JSON 的段内锚点完全同序；译文注释标记与尾注定义完全同序；成品不残留结构标记；空白页不制造空正文块；正文段落与展示引文按 PDF 行首缩进和字体层级正确区分；全书进度仅在本章 QA PASS 后进入下一章。HTML 需用真实浏览器至少检查 1366×768、1920×1080 与 390×844，逐一打开本章所有注释，并验证再次点击、点击外部与 Escape 关闭。

退出码：0 PASS；1 WARN（不影响内容完整性的人工判断项）；2 FAIL（结构、内容、资源、交互或同步错误）。每次写入 `reports/qa.json` 与 `reports/QA_REPORT.md`。

## 正式渲染前的完整性门

“结构已经建立”不等于“翻译已经完整”。正式渲染前必须生成 `reports/chapter-XX/PRE_RENDER_GATE.md`，并且只有 `PRE_RENDER_DECISION: PASS` 才允许生成 HTML 或 Markdown。

- source JSON 中的每个 block 必须在 zh JSON 中存在一次且仅一次，并有非空完整译文。
- 普通长段出现异常短译文、整句英文残留、页面锚点或注释标记缺失时直接 FAIL；长度比例只负责发现异常，不能替代逐段语义复核。
- 注释必须独立核对数量和译文覆盖；任何缺号、空译或异常缩写均 FAIL。
- 图片图注必须独立核对数量和译文覆盖；任何缺失或空译均 FAIL。
- 被 QA 拒绝的译稿必须移入 `rejected` 范围或明确标记 rejected；实质性完整性失败采用干净重译，不得把局部修补后的旧稿直接发布。
- `.tmp`、rejected 草稿和不完整模型缓存不属于规范输入，预渲染门及正式编译不得读取它们。
- 长章节应维护可续跑的批次状态，逐 block 记录翻译和复核结果。
